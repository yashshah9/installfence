## 1. Executive Summary

Deliver a **minimal viable open-source foundation** for sandboxed package installation. v0.1 wraps `pip`, `uv`, `npm`, and arbitrary commands in a Linux bubblewrap sandbox driven by YAML policy — a single static Go binary with CI-ready tests and Docker dev environment. No violation reporting or macOS backend yet; the goal is to prove the sandbox wrapper works and is usable from day one.

---

## 2. Problem Statement

- Package install hooks (`pip install`, `npm install`, `uv sync`) execute arbitrary code with full user privileges
- npm 12 blocks lifecycle scripts by default, but approved scripts still run unsandboxed
- Python has no equivalent protection — every `pip install` can read `~/.ssh`, cloud credentials, and `.env` files
- Existing container-only solutions add friction; developers need a drop-in CLI wrapper

## 4. Non-Goals (v0.1)

- Violation reporting (log blocked file/network access attempts)
- macOS `sandbox-exec` or Windows backend
- Shell shims for transparent PATH interception
- npm 12 install-script allowlist integration
- Top-N package compatibility test matrix
- Network egress filtering beyond `--unshare-net`
- Env-var stripping at runtime (policy defines keys; enforcement deferred)

## 5. Architecture Delivered

```
installfence CLI (cobra)
  ├── health          → sandbox availability check
  ├── run [cmd...]    → arbitrary command wrapper
  ├── pip / uv / npm  → tool-specific passthrough wrappers
  │
  ├── policy loader   → internal/policy (YAML + defaults)
  └── sandbox runner  → internal/sandbox (bubblewrap builder)
          └── passthrough fallback (dry-run or bwrap missing)
```

### Data Flow

```
User command
    → Load policy (--policy PATH or defaults)
    → Apply --dry-run flag if set
    → HasBubblewrap()?
         ├── yes → build bwrap args → exec bwrap
         └── no  → exec passthrough (stderr warning)
    → Return exit code + message on stderr
```

### Technology Choices

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Language | Go 1.22 | Single static binary, cross-compile, no runtime deps |
| CLI | cobra | Standard Go CLI framework, subcommand composition |
| Sandbox | bubblewrap (`bwrap`) | Kernel namespaces, no daemon, widely packaged on Linux |
| Policy | YAML (`gopkg.in/yaml.v3`) | Human-readable, version-controllable per project |
| Quality | `go test`, GitHub Actions | Minimal toolchain, fast CI |

### bubblewrap Invocation (v0.1)

| Flag | Purpose |
|------|---------|
| `--unshare-all` | Isolate PID, mount, IPC, UTS, cgroup namespaces |
| `--die-with-parent` | Kill sandbox when installfence exits |
| `--ro-bind / /` | Read-only root filesystem |
| `--dev /dev` | Device nodes for build tools |
| `--proc /proc` | Process table |
| `--tmpfs /tmp` | Writable temp space |
| `--tmpfs <hide_path>` | Hide secret paths by masking with empty tmpfs |
| `--unshare-net` | Applied when `allow_network: false` |
| `-- <cmd>` | User command passthrough |

### 6.3 Global Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--policy PATH` | (empty → built-in defaults) | Custom policy YAML path |
| `--dry-run` | `false` | Print sandbox plan; run command without bwrap enforcement |

### 6.4 Policy Schema (v0.1)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `hide_paths` | `[]string` | `~/.ssh`, `~/.aws`, `~/.gnupg`, `.env` | Paths masked with tmpfs in sandbox |
| `hide_env_keys` | `[]string` | `AWS_SECRET_ACCESS_KEY`, `GITHUB_TOKEN`, `NPM_TOKEN`, `OPENAI_API_KEY` | Declared for future env stripping |
| `allow_network` | `bool` | `true` | When `false`, adds `--unshare-net` |
| `dry_run` | `bool` | `false` | Set internally when `--dry-run` flag passed |

### 6.5 Fallback Behavior

| Condition | Behavior | User-visible message |
|-----------|----------|----------------------|
| `--dry-run` set | Passthrough exec, no bwrap | `dry-run: would sandbox command` |
| bwrap not on PATH | Passthrough exec with warning | `bwrap not found; running passthrough (unsafe)` |
| bwrap available | Full sandbox | `sandboxed with bubblewrap` |

## 8. Known Limitations (v0.1)

| Limitation | Impact | Planned fix |
|------------|--------|-------------|
| Linux bubblewrap only | macOS/Windows users get passthrough fallback | v0.2 M2 macOS `sandbox-exec` |
| No violation reporting | Blocked access attempts are silent | v0.2 M1 violation log + exit codes |
| Passthrough when bwrap missing | Unsafe execution without user opt-in block | v0.2 `--require-sandbox` flag |
| `hide_env_keys` not enforced at runtime | Env vars still visible inside sandbox | v0.2 env scrubbing in bwrap `--setenv` |
| Path hiding via tmpfs only | Does not block all secret locations (e.g., `/run/user`) | v0.2 expanded default policy |
| No install-script allowlist | npm 12 approved scripts still unsandboxed without wrapper | v0.2 M5 npm integration |
| Native builds may need policy exceptions | Compiler access to system headers can fail under strict ro-bind | Documented in README; per-project policy overrides |
